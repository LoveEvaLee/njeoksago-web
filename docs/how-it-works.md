# 동작 원리 — 판정은 어떻게 계산되나요

N적사고의 설계 원칙은 한 줄로 요약됩니다. **"언어 모델은 추출까지, 판정은 코드가."** 꿈을 읽어내는 유연함은 언어 모델에게 맡기되, 길흉을 가르는 판단은 누가 돌려도 같은 답이 나오는 결정적 계산으로 못 박았습니다. 해몽처럼 듣는 사람의 기대에 휩쓸리기 쉬운 영역일수록, 판단 과정이 재현 가능해야 한다고 보기 때문입니다.

## 1단계 — 추출

꿈 문장에서 두 가지를 읽어냅니다.

- **상징(concept)**: 등장한 소재 — 뱀, 이빨, 돈, 옛 애인, 화산…
- **장면 전개(facts)**: 어떻게 흘러갔는지 — 행동(물림 · 잡음 · 잃음…), 결말(해결됨 · 붙잡힘 · 벗어남…), 감정, 다친 여부 같은 축

여기서 멈춥니다. "뱀이 나왔으니 재물운"처럼 해석을 지어내는 일은 추출 단계에서 금지되어 있습니다. 이 공개판은 서버 없이 돌아가도록 브라우저 안의 경량 패턴 매처가 추출을 맡습니다.

## 2단계 — 근거 매칭

추출된 상징·전개를 지식베이스의 해석 규칙과 대조합니다. 규칙 하나는 대략 이렇게 생겼습니다.

```json
{
  "concept": "shark",
  "condition": { "scene.injury": "none" },
  "claim": "상어에게 물렸지만 다치지 않은 꿈은 권리·명예를 얻는 길조",
  "direction": "길",
  "grade": "B"
}
```

- **조건 일치도**: 꿈의 전개가 규칙의 조건과 전부 맞으면 1.0, 조건 축이 아직 확인되지 않았으면 0.5(부분 일치), 서로 어긋나면 0점입니다. 부분 일치만 있는 근거는 화면에서 단정 인용하지 않습니다.
- **등급(grade)**: 서로 다른 문헌 계보가 같은 방향으로 읽으면 등급이 올라갑니다(2계보 합의 = B, 3계보 = A). 한 계보만 말하는 해석은 낮은 가중치로만 반영됩니다.
- 웹에서 수집한 해몽 담론의 집계 수치(어느 쪽 읽기가 많은지)는 **참고 신호로만** 쓰고, 판정 가중치에는 넣지 않습니다.

## 3단계 — 판정

모든 근거의 가중 점수를 모아 코드가 계산합니다.

| 계산 | 의미 |
|---|---|
| 근거 총량이 기준 미달 | **판정 유보** — 모르는 것을 아는 척하지 않습니다 |
| 방향성 근거 비중이 낮음 | **중립** — 일상의 잔상으로 봅니다 |
| 균형값 \|balance\| ≥ 0.6 + 확실한 근거 1개 이상 | **길몽 / 흉몽** 확정 |
| 그 밖 | **혼합** — 길·흉을 그대로 병기합니다 |

균형값(balance)은 (길 점수 − 흉 점수) / (길 + 흉)로, 화면의 BALANCE 눈금이 이 값입니다. 계산에 쓰는 계수는 전부 `kb.json`의 `scoring` 항목에 공개되어 있어, 누구든 같은 입력으로 같은 판정을 재현할 수 있습니다.

## 치우침을 막는 장치

해몽 서비스가 빠지기 쉬운 함정마다 방화벽을 하나씩 세워 두었습니다. 대표적인 것만 들면 —

- **아첨 금지**: 판정 문구는 근거의 claim을 원문 그대로 인용해 조립합니다. 듣기 좋으라고 문장을 새로 지어내는 경로가 없습니다.
- **소수 의견 보존**: 판정에 반영되지 못한 반대 읽기도 "이렇게 읽는 계보도 있습니다"로 따로 보여줍니다.
- **갈림 공개**: 문헌 계보끼리 해석이 갈리는 상징은 갈린다고 표시하지, 한쪽을 조용히 지우지 않습니다.
- **사람 검수 게이트**: 새 규칙은 자동 반영되지 않고, 문헌 대조 → 회귀 검증(골든셋) → 사람 승인 순서를 전부 통과해야 들어옵니다.

## 한계

- 상징 사전에 없는 소재는 판정이 유보됩니다. 유보된 표현은 보완 후보로 수집됩니다.
- 전통 문헌의 읽기를 정리해 보여줄 뿐, 심리 상담이나 의학적 조언을 대신하지 않습니다.
